# ตารางสื่อความหมายสัญลักษณ์ (Diagram Legends)

เอกสารนี้รวบรวมตารางอธิบายสัญลักษณ์ที่ใช้ในแผนภาพต่างๆ ของบทที่ 3 (System Design) เพื่อให้เข้าใจความหมายของสัญลักษณ์ได้ถูกต้องตรงกัน

---

## 1. สัญลักษณ์ในแผนภาพคลาส (Class Diagram)

ตารางแสดงความหมายของสัญลักษณ์ที่ใช้ใน Class Diagram (สอดคล้องกับหัวข้อ 3.5)

| สัญลักษณ์ (Symbol) | ชื่อเรียก (Name) | ความหมาย (Description) |
| :---: | :--- | :--- |
| **Class** | Class Box | **กล่องแสดงคลาส** ประกอบด้วย 3 ส่วนหลัก: <br>1. *Class Name* (ชื่อคลาส) <br>2. *Attributes* (คุณสมบัติ/ตัวแปร) <br>3. *Methods* (พฤติกรรม/ฟังก์ชัน) |
| ![Inheritance](https://plantuml.com/img/icon_inheritance.png) <br> *(หัวลูกศรสามเหลี่ยมโปร่ง)* | Generalization | **การสืบทอด (Inheritance)** ใช้แสดงว่าคลาสลูก (Subclass) สืบทอดคุณสมบัติและพฤติกรรมมาจากคลาสแม่ (Superclass) |
| ![Composition](https://plantuml.com/img/icon_composition.png) <br> *(หัวเพชรทึบ)* | Composition | **องค์ประกอบ (Composition)** ความสัมพันธ์แบบ "ขาดจากกันไม่ได้" หรือ "เป็นส่วนหนึ่งของ" หากคลาสหลักถูกทำลาย คลาสส่วนประกอบจะถูกทำลายด้วย (เช่น Tournament ถูกลบ Match ก็จะหายไป) |
| ![Association](https://plantuml.com/img/icon_association.png) <br> *(เส้นทึบ)* | Association | **ความสัมพันธ์ทั่วไป** แสดงการเชื่อมโยงระหว่างคลาสที่ทำงานร่วมกันหรือรู้จักกัน (เช่น User มีความเกี่ยวข้องกับ Profile) |
| ![Dependency](https://plantuml.com/img/icon_dependency.png) <br> *(เส้นประหัวลูกศร)* | Dependency | **การพึ่งพา (Dependency)** แสดงว่าคลาสหนึ่งเรียกใช้หรือพึ่งพาอีกคลาสหนึ่งเพียงชั่วคราว (เช่น View เรียกใช้งาน Form ในการประมวลผล) |
| **1, 0..*, 1..*** | Multiplicity | **จำนวนความสัมพันธ์** ตัวเลขกำกับที่ปลายเส้นความสัมพันธ์:<br>• `1` : หนึ่งเดียว (One)<br>• `0..1` : ศูนย์หรือหนึ่ง (Zero or One)<br>• `0..*` : ศูนย์หรือหลาย (Zero or Many)<br>• `1..*` : หนึ่งหรือหลาย (One or Many) |
| **<<PK>>** | Primary Key | **คีย์หลัก (Primary Key)** ใช้ระบุว่าแอตทริบิวต์นี้เป็นคีย์หลักของตารางในฐานข้อมูล (ใช้ใน Backend Model) |
| **<<FK>>** | Foreign Key | **คีย์นอก (Foreign Key)** ใช้ระบุว่าแอตทริบิวต์นี้เป็นคีย์นอกที่อ้างอิงไปยังตารางอื่น (ใช้ใน Backend Model) |

## 2. สัญลักษณ์ในแผนภาพลำดับ (Sequence Diagram)

ตารางแสดงความหมายของสัญลักษณ์ที่ใช้ใน Sequence Diagram (สอดคล้องกับหัวข้อ 3.6)

| สัญลักษณ์ (Symbol) | ชื่อเรียก (Name) | ความหมาย (Description) |
| :---: | :--- | :--- |
| ![Actor](https://plantuml.com/img/icon_actor.png) | Actor | **ผู้กระทำ** ผู้ใช้งานหรือระบบภายนอกที่มีปฏิสัมพันธ์กับระบบ (เช่น ผู้เยี่ยมชม, สมาชิก, ผู้ดูแลระบบ) |
| **Lifeline** | Lifeline | **เส้นชีวิต** เส้นประแนวตั้งแสดงถึงช่วงเวลาที่ออบเจกต์หรือคลาสมีตัวตนอยู่ในกระบวนการ |
| **Activation Bar** | Activation Bar | **แถบการทำงาน** แท่งสี่เหลี่ยมบน Lifeline แสดงช่วงเวลาที่ออบเจกต์กำลังประมวลผล (Active) |
| **──➤** <br> *(หัวลูกศรทึบ)* | Synchronous Message | **ข้อความแบบซิงโครนัส** การส่งคำสั่งแบบรอการตอบกลับ (เส้นทึบหัวลูกศรทึบ) เช่น การเรียกใช้ View หรือ API |
| **<--** <br> *(เส้นประ)* | Return Message | **ข้อความตอบกลับ** การส่งผลลัพธ์หรือข้อมูลกลับไปยังผู้เรียก (เส้นประหัวลูกศรเปิด) เช่น การส่ง Template กลับไปแสดงผล |
| **alt / else** | Alternative Fragment | **ทางเลือก (Alternative)** กรอบแสดงเงื่อนไขการทำงาน (If-Else) เช่น การตรวจสอบว่า Login สำเร็จหรือไม่ |
| **loop** | Loop Fragment | **การวนซ้ำ (Loop)** กรอบแสดงการทำงานซ้ำ เช่น การวนลูปดึงข้อมูลผู้เข้าแข่งขันมาแสดงในหน้าเว็บ |

## 3. สัญลักษณ์ในแบบจำลองข้อมูล (ER Diagram)

ตารางแสดงความหมายของสัญลักษณ์แบบ Crow's Foot Notation (สอดคล้องกับหัวข้อ 3.7)

| สัญลักษณ์ (Symbol) | ชื่อเรียก (Name) | ความหมาย (Description) |
| :---: | :--- | :--- |
| **Entity** | Entity | **เอนทิตี (ตาราง)** กล่องสี่เหลี่ยมแสดงชื่อตารางและรายชื่อฟิลด์ (Attributes) ภายในตาราง |
| **PK** | Primary Key | **คีย์หลัก** ฟิลด์ที่ใช้ระบุความแตกต่างของข้อมูลในแต่ละแถว ไม่สามารถซ้ำกันได้ |
| **FK** | Foreign Key | **คีย์นอก** ฟิลด์ที่ใช้อ้างอิงไปยัง PK ของตารางอื่น เพื่อสร้างความสัมพันธ์ |
| **\|\|--\|\|** | One-to-One | **หนึ่งต่อหนึ่ง** ข้อมูล 1 แถวในตาราง A สัมพันธ์กับข้อมูล 1 แถวในตาราง B (เช่น User กับ Profile) |
| **\|\|--o{** | One-to-Many | **หนึ่งต่อกลุ่ม** ข้อมูล 1 แถวในตาราง A สัมพันธ์กับข้อมูลหลายแถวในตาราง B (เช่น User สร้างได้หลาย Tournament) |
| **}o--\|\|** | Many-to-One | **กลุ่มต่อหนึ่ง** ข้อมูลหลายแถวในตาราง A สัมพันธ์กับข้อมูล 1 แถวในตาราง B (เช่น หลาย Match อยู่ใน 1 Tournament) |
| **\|\|** | Mandatory One | **ต้องมีหนึ่งเท่านั้น** ขีดสองขีดแนวตั้ง แสดงว่าความสัมพันธ์ด้านนั้นต้องมีข้อมูลอย่างน้อย 1 และมากที่สุด 1 |
| **\|{** | Mandatory Many | **ต้องมีอย่างน้อยหนึ่ง** ขีดแนวตั้งและตีนกา แสดงว่าความสัมพันธ์ด้านนั้นต้องมีข้อมูลอย่างน้อย 1 (Many) |
| **o\|** | Optional One | **มีศูนย์หรือหนึ่ง** วงกลมและขีดแนวตั้ง แสดงว่าความสัมพันธ์ด้านนั้นอาจไม่มีข้อมูลเลย หรือมีได้แค่ 1 (Nullable) |
| **o{** | Optional Many | **มีศูนย์หรือหลาย** วงกลมและตีนกา แสดงว่าความสัมพันธ์ด้านนั้นอาจไม่มีข้อมูลเลย หรือมีได้หลายข้อมูล (Zero or Many) |

---
*หมายเหตุ: สัญลักษณ์เหล่านี้อ้างอิงตามมาตรฐาน UML (Unified Modeling Language) และ Crow's Foot Notation ที่ใช้ในการออกแบบระบบ BattleHub*

## 4. สัญลักษณ์ในแผนภาพกรณีการใช้งาน (Use Case Diagram)

ตารางแสดงความหมายของสัญลักษณ์ที่ใช้ใน Use Case Diagram (สอดคล้องกับหัวข้อ 3.4)

| สัญลักษณ์ (Symbol) | ชื่อเรียก (Name) | ความหมาย (Description) |
| :---: | :--- | :--- |
| ![Actor](https://plantuml.com/img/icon_actor.png) | Actor | **ผู้กระทำ (Actor)** ผู้ใช้งานหรือระบบภายนอกที่มีปฏิสัมพันธ์กับระบบ (เช่น Guest, Member, Admin) |
| **(Use Case)** | Use Case | **กรณีการใช้งาน (Use Case)** วงรีแสดงฟังก์ชันการทำงานหรือบริการที่ระบบจัดเตรียมให้ผู้ใช้ (เช่น Login, Vote) |
| **───** <br> *(เส้นทึบ)* | Association | **ความสัมพันธ์ (Association)** เส้นเชื่อมโยงระหว่าง Actor กับ Use Case เพื่อแสดงว่าใครสามารถใช้งานฟังก์ชันนั้นได้ |
| **System Boundary** | System Boundary | **ขอบเขตระบบ (System Boundary)** กรอบสี่เหลี่ยมที่ล้อมรอบ Use Case ทั้งหมด เพื่อแบ่งแยกสิ่งที่อยู่ภายในระบบและภายนอกระบบ |
