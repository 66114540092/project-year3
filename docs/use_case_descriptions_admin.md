# Use Case Description — ระบบ BattleHub (UC-26 ถึง UC-35)

## ส่วนที่ 3: Admin (ผู้ดูแลระบบ)

---

### ตารางที่ 26: UC-26 ดูแดชบอร์ด

| รายการ | รายละเอียด |
|--------|-----------|
| **Use Case ID** | UC-26 |
| **Use Case Name** | ดูแดชบอร์ด (View Dashboard) |
| **Actor** | Admin |
| **Pre-condition** | 1. ผู้ดูแลระบบเข้าสู่ระบบแล้ว 2. ผู้ดูแลระบบมีสิทธิ์ Staff |
| **Post-condition** | ข้อมูลภาพรวมของระบบถูกแสดงผลบนหน้าจอ |

**Main Flow:**
1. ผู้ดูแลระบบทำการเข้าสู่หน้า Admin Panel
2. ระบบดำเนินการดึงข้อมูลสถิติจากฐานข้อมูล (จำนวนผู้ใช้ ทัวร์นาเมนต์ รายงาน)
3. ข้อมูลสถิติถูกแสดงผลในรูปแบบการ์ดสรุป (Stats Cards)
4. ตารางกิจกรรมล่าสุด (Recent Activity) ถูกแสดงผลโดยระบบ
5. เมนูนำทางไปยังส่วนจัดการต่าง ๆ ถูกแสดงผลบนแถบด้านข้าง (Sidebar)

---

### ตารางที่ 27: UC-27 จัดการผู้ใช้งาน

| รายการ | รายละเอียด |
|--------|-----------|
| **Use Case ID** | UC-27 |
| **Use Case Name** | จัดการผู้ใช้งาน (Manage Users) |
| **Actor** | Admin |
| **Pre-condition** | 1. ผู้ดูแลระบบเข้าสู่ระบบแล้ว 2. ผู้ดูแลระบบมีสิทธิ์ Staff |
| **Post-condition** | รายชื่อผู้ใช้งานทั้งหมดถูกแสดงผลบนหน้าจอ |

**Main Flow:**
1. ผู้ดูแลระบบทำการเข้าสู่หน้าจัดการผู้ใช้งานผ่าน Admin Panel
2. ระบบดำเนินการดึงข้อมูลผู้ใช้งานทั้งหมดจากฐานข้อมูล
3. รายชื่อผู้ใช้งานถูกแสดงผล พร้อมข้อมูลสถานะ วันที่สมัคร และจำนวนทัวร์นาเมนต์ที่สร้าง
4. ตัวกรองและช่องค้นหาถูกแสดงผลสำหรับการค้นหาผู้ใช้งาน
5. ผู้ดูแลระบบสามารถเลือกผู้ใช้งานเพื่อดำเนินการเพิ่มเติม (แบน/ปลดแบน/ลบ) ได้

---

### ตารางที่ 28: UC-28 แบน/ปลดแบนผู้ใช้งาน

| รายการ | รายละเอียด |
|--------|-----------|
| **Use Case ID** | UC-28 |
| **Use Case Name** | แบน/ปลดแบนผู้ใช้งาน (Ban / Unban User) |
| **Actor** | Admin |
| **Pre-condition** | 1. ผู้ดูแลระบบอยู่ในหน้าจัดการผู้ใช้งาน 2. มีผู้ใช้งานที่ต้องการดำเนินการ |
| **Post-condition** | สถานะของผู้ใช้งานถูกเปลี่ยนแปลง (Active/Banned) และ Audit Log ถูกบันทึก |

**Main Flow:**
1. ผู้ดูแลระบบทำการเลือกผู้ใช้งานที่ต้องการดำเนินการ
2. ปุ่ม "Ban" หรือ "Unban" ถูกแสดงผลตามสถานะปัจจุบันของผู้ใช้งาน
3. เมื่อปุ่มถูกกด กล่องยืนยันการดำเนินการถูกแสดงผลโดยระบบ
4. ระบบดำเนินการเปลี่ยนสถานะผู้ใช้งาน (is_active) ในฐานข้อมูล
5. Audit Log ถูกสร้างขึ้นอัตโนมัติเพื่อบันทึกการดำเนินการ พร้อมข้อความแจ้งผลสำเร็จ

---

### ตารางที่ 29: UC-29 ลบผู้ใช้งาน

| รายการ | รายละเอียด |
|--------|-----------|
| **Use Case ID** | UC-29 |
| **Use Case Name** | ลบผู้ใช้งาน (Delete User) |
| **Actor** | Admin |
| **Pre-condition** | 1. ผู้ดูแลระบบอยู่ในหน้าจัดการผู้ใช้งาน 2. ผู้ใช้งานเป้าหมายไม่ใช่ Superuser |
| **Post-condition** | ผู้ใช้งานและข้อมูลที่เกี่ยวข้องถูกลบออกจากระบบ และ Audit Log ถูกบันทึก |

**Main Flow:**
1. ผู้ดูแลระบบทำการเลือกผู้ใช้งานที่ต้องการลบ
2. เมื่อปุ่ม "Delete" ถูกกด กล่องยืนยันการลบถูกแสดงผลโดยระบบ
3. ผู้ดูแลระบบทำการยืนยันการลบ
4. ระบบดำเนินการลบผู้ใช้งานและข้อมูลที่เกี่ยวข้องทั้งหมดออกจากฐานข้อมูล
5. Audit Log ถูกสร้างขึ้นอัตโนมัติ พร้อมข้อความแจ้งผลสำเร็จ

### ตารางที่ 30: UC-30 ดูแลทัวร์นาเมนต์

|--------|-----------|

### ตารางที่ 31: UC-31 บังคับจบทัวร์นาเมนต์

| รายการ | รายละเอียด |
|--------|-----------|
| **Use Case ID** | UC-31 |
| **Use Case Name** | บังคับจบทัวร์นาเมนต์ (Force Finish Tournament) |
| **Actor** | Admin |
| **Pre-condition** | 1. ผู้ดูแลระบบอยู่ในหน้าดูแลทัวร์นาเมนต์ 2. ทัวร์นาเมนต์อยู่ในสถานะ "Open" หรือ "Waiting" |
| **Post-condition** | ทัวร์นาเมนต์ถูกเปลี่ยนสถานะเป็น "Finished" และ Audit Log ถูกบันทึก |

3. ผู้ดูแลระบบทำการยืนยันการดำเนินการ
4. ระบบดำเนินการเปลี่ยนสถานะทัวร์นาเมนต์เป็น "Finished" ในฐานข้อมูล
5. Audit Log ถูกสร้างขึ้นอัตโนมัติ พร้อมข้อความแจ้งผลสำเร็จ

### ตารางที่ 32: UC-32 จัดการรายงานปัญหา

| รายการ | รายละเอียด |
|--------|-----------|
| **Use Case ID** | UC-32 |
| **Use Case Name** | จัดการรายงานปัญหา (Manage Reports) |
| **Actor** | Admin |
| **Pre-condition** | 1. ผู้ดูแลระบบเข้าสู่ระบบแล้ว 2. มีรายงานปัญหาในระบบ |
| **Post-condition** | รายการรายงานปัญหาถูกแสดงผลพร้อมตัวเลือกการดำเนินการ |

**Main Flow:**
1. ผู้ดูแลระบบทำการเข้าสู่หน้าจัดการรายงานปัญหาผ่าน Admin Panel
2. ระบบดำเนินการดึงข้อมูลรายงานปัญหาทั้งหมดจากฐานข้อมูล
3. รายงานถูกแสดงผล พร้อมข้อมูลผู้รายงาน เป้าหมาย เหตุผล และสถานะ
4. สถิติจำนวนรายงานแยกตามสถานะ (Pending/Resolved/Dismissed) ถูกแสดงผลโดยระบบ
5. ผู้ดูแลระบบสามารถกรองรายงานตามสถานะ และเลือกรายงานเพื่อดำเนินการได้

---

### ตารางที่ 33: UC-33 ดำเนินการรายงาน

| รายการ | รายละเอียด |
|--------|-----------|
| **Use Case ID** | UC-33 |
| **Use Case Name** | ดำเนินการรายงาน (Resolve / Dismiss Report) |
| **Actor** | Admin |
| **Pre-condition** | 1. ผู้ดูแลระบบอยู่ในหน้าจัดการรายงานปัญหา 2. รายงานอยู่ในสถานะ "Pending" |
| **Post-condition** | สถานะรายงานถูกเปลี่ยนเป็น "Resolved" หรือ "Dismissed" และ Audit Log ถูกบันทึก |

**Main Flow:**
1. ผู้ดูแลระบบทำการเลือกรายงานปัญหาที่ต้องการดำเนินการ
2. ข้อมูลรายละเอียดของรายงานถูกแสดงผลโดยระบบ
3. ผู้ดูแลระบบเลือกกดปุ่ม "Resolve" (ดำเนินการแล้ว) หรือ "Dismiss" (ยกเลิก)
4. ระบบดำเนินการเปลี่ยนสถานะรายงานในฐานข้อมูล
5. Audit Log ถูกสร้างขึ้นอัตโนมัติ พร้อมข้อความแจ้งผลสำเร็จ

### ตารางที่ 34: UC-34 ลบความคิดเห็น

| รายการ | รายละเอียด |
|--------|-----------|
| **Use Case ID** | UC-34 |
| **Use Case Name** | ลบความคิดเห็น (Delete Comment) |
| **Actor** | Admin |
| **Pre-condition** | 1. ผู้ดูแลระบบเข้าสู่ระบบแล้ว 2. มีความคิดเห็นที่ถูกรายงานหรือไม่เหมาะสม |

3. ผู้ดูแลระบบทำการยืนยันการลบ
4. ระบบดำเนินการลบความคิดเห็นออกจากฐานข้อมูล
5. Audit Log ถูกสร้างขึ้นอัตโนมัติ พร้อมข้อความแจ้งผลสำเร็จ

### ตารางที่ 35: UC-35 ดูบันทึกการดำเนินการ

| รายการ | รายละเอียด |
|--------|-----------|
| **Use Case ID** | UC-35 |
| **Use Case Name** | ดูบันทึกการดำเนินการ (View Audit Logs) |
| **Actor** | Admin |
| **Pre-condition** | 1. ผู้ดูแลระบบเข้าสู่ระบบแล้ว 2. ผู้ดูแลระบบมีสิทธิ์ Staff |
| **Post-condition** | รายการบันทึกการดำเนินการทั้งหมดถูกแสดงผลบนหน้าจอ |

**Main Flow:**
1. ผู้ดูแลระบบทำการเข้าสู่หน้า Audit Logs ผ่าน Admin Panel
2. ระบบดำเนินการดึงข้อมูลบันทึกการดำเนินการทั้งหมดจากฐานข้อมูล
3. รายการบันทึกถูกแสดงผลในรูปแบบตาราง ประกอบด้วย ผู้ดำเนินการ ประเภทการกระทำ เป้าหมาย และวันเวลา
4. ข้อมูลถูกเรียงลำดับจากล่าสุดไปเก่าสุด พร้อมระบบแบ่งหน้า (Pagination)
5. ผู้ดูแลระบบสามารถตรวจสอบประวัติการดำเนินการทั้งหมดของผู้ดูแลระบบทุกคนได้
